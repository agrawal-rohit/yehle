`yehle` is a CLI tool for scaffolding modern software projects by performing common [yak-shaving](https://softwareengineering.stackexchange.com/a/388236) operations through opinionated templates, sensible tooling setup, and development best practices.

Here's what `yehle` offers:

  <Card icon={<Workflow className="text-blue-300" />} title="Build and Release Workflows" href="/docs/features/ci-automation">

## Motivation

I'd usually spend hours re-configuring the _"same old tooling and workflow setup"_ every time I started a new project — instead of focusing on the actual functionality. The same pattern shows up for teams: **standard** scaffolding stays stable for months until a new project type or workflow appears, and suddenly everything gets reconfigured again. I built `yehle` to remove that repetition: it generates a project structure _(based on my personal flavour)_ with essential pieces already configured — pre-commit hooks, a linter and formatter, CI and release workflows, basic documentation, and more — so a new repo starts in a **known-good** state and you can build what you care about without the distractions.

## What you get

- Opinionated project templates (currently **TypeScript** packages — see [Supported languages](/docs/supported-languages))
- Pre-configured development tooling (lint/format, tests, type checking)
- CI and release workflows suitable for open-source projects
- Optional **agent instructions** for your IDE ([Agent instructions](/docs/features/agent-instructions))

## Requirements

[Node.js v20+](https://nodejs.org)

## Install and run

You interact with `yehle` through **`package`** (scaffold a project) and **`instructions`** (add IDE rules to an existing repo):

```bash
npx yehle package
npx yehle instructions
```

The easiest way to start is to call the CLI through [npx](https://www.npmjs.com/package/npx):

```bash
npx yehle package
```

<Callout type="warn">
  Some workflows in the generated projects may require repository secrets to be configured in your
  GitHub project under **Settings → Secrets and variables → Actions**. Additionally, ensure that
  **"Allow GitHub Actions to create and approve pull requests"** is enabled under **Settings →
  Actions → General** to prevent workflow failures before you publish your code.
</Callout>

`yehle` uses a **tag-driven release workflow** for packages configured for publishing. See [Release workflow](/docs/features/release-workflow).

### Examples

**Public TypeScript package**

```bash
npx yehle package \
  --name my-package \
  --lang typescript \
  --template basic \
  --public
```

**Private internal TypeScript library**

```bash
npx yehle package \
  --name internal-utils \
  --lang typescript \
  --template basic
```

**React + Vite package**

```bash
npx yehle package \
  --name my-react-package \
  --lang typescript \
  --template react \
  --public
```

Full flag reference: [API Reference — `package`](/docs/commands/package).
