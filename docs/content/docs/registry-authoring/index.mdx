## Installing the core package

```bash
pnpm add @tuckshop/core
```

## What `@tuckshop/core` provides

- registry schema types
- `parseRegistryDocument()` and `parseWithSchema()` for runtime validation (unknown keys are rejected)
- `buildRegistry()` to compile an authoring tree into `registry.json` plus payloads and scripts under `r/`
- install hook contracts (`BeforeInstallHook`, `AfterInstallHook`, `ConditionHandler`) and local-only runners (`runBeforeInstallHook`, `runAfterInstallHook`)

## Compiling a registry

```ts
import path from "node:path";
import { buildRegistry } from "@tuckshop/core";

await buildRegistry({
	sourceDir: path.join(packageRoot, "registry"),
	outDir: packageRoot,
});
```

That writes:

- `registry.json` — catalog index (items may declare `source`, `variants`, and/or `beforeInstall` / `afterInstall`)
- `r/{itemId}.json` or `r/{itemId}/{variantId}.json` — install payloads
- `r/{itemId}.beforeInstall.{index}.js` / `r/{itemId}.afterInstall.{index}.js` — bundled install scripts
- `r/_handlers/{key}.handler.js` — bundled condition handlers

## Install lifecycle (local catalogs only)

Every item has two optional authored phases. **Write** (static payload files) is core and not a script.

| Phase | When it runs | Typical use |
| --- | --- | --- |
| `beforeInstall` | Before planned files are written | Prompts, generate/transform the file list, scaffold CLIs |
| write | After `beforeInstall` | Static `files` plus any files returned from `beforeInstall` |
| `afterInstall` | After files exist on disk | `git init`, format, convert |

Each phase accepts a **string or array of strings**. Each entry is a **colocated script** — any relative path under the item folder (`license.ts`, `./scaffold.ts`, `scripts/setup`). Item ids belong in `registryDependencies`, not in these lists.

Scripts are bundled at compile time and executed only when the catalog is a **local path**. Remote HTTPS registries cannot execute custom scripts.

Use `import type` from `@tuckshop/core` (do not runtime-import the package):

```ts
import type { BeforeInstallHook } from "@tuckshop/core";

const beforeInstall: BeforeInstallHook = async (ctx) => {
	const licenseId = await ctx.prompts.select("License", {
		options: [{ label: "MIT", value: "MIT" }],
	});
	return {
		files: [{ target: "LICENSE", content: licenseId }],
	};
};

export default beforeInstall;
```

`beforeInstall` may prompt (`ctx.prompts`), run commands (`ctx.run`), and return `files` / `variables`. Returned `files` **replace** `ctx.files` (append with `[...ctx.files, ...extra]` when needed). `afterInstall` uses the same function type, but returned `files` are ignored.

Shared prompts stay on conditions and `uses`. Condition handlers expose `infer` to suggest a prompt default (for example from marker files or `ctx.run("git config --get user.name")`). Items consume those values with `"uses": ["authorName"]`; the captured value is then `ctx.conditions.authorName` in install scripts.

Shared conditions declare a `kind`:

- `select` (default) — single choice from `values`
- `multiselect` — multiple choices from `values` (`ctx.conditions` stores `string[]`)
- `text` — free-form string
- `boolean` — yes/no (`ctx.conditions` stores `boolean`)

Variant `when` may reference `select`, `multiselect`, and `boolean` keys (`"true"` / `"false"` for booleans). Text conditions are for prompts/`uses` only.

### Composing templates

`registryDependencies` install other items **before** the consumer. They are not lifecycle phases. Each dependency runs its own `beforeInstall` / write / `afterInstall` when it is installed.

```json
{
	"id": "react-app-template",
	"registryDependencies": ["create-react-app-scaffold", "license-configuration", "git-init"]
}
```

A reusable `git-init` item is just an item whose only phase is `afterInstall`. Because it is a dependency, that script runs when `git-init` is installed — before the consumer's files. To run a command after *this* item's writes, list a colocated script on the item:

```json
{
	"id": "license-configuration",
	"uses": ["authorName"],
	"beforeInstall": "license.ts"
}
```

## Validating artefacts

```ts
import { parseRegistryDocument } from "@tuckshop/core";

const registry = parseRegistryDocument(JSON.parse(registryJson));
```

Unknown item types are allowed as long as the document shape is valid, so you can extend the registry model without forking the CLI.
