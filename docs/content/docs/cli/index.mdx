## Default behavior

`npx tuckshop` uses the default registry bundled into the CLI package.

```bash
npx tuckshop list
```

## Adding registry items

Install items from the bundled or custom registry into the current project:

```bash
npx tuckshop add pr-template-configuration
npx tuckshop add testing-configuration --overwrite
npx tuckshop add
```

`add` resolves variants from shared registry conditions (local condition handlers can suggest prompt defaults), fetches install payloads from the catalog location, runs any local item handlers, writes files into the project, and optionally installs packages per ecosystem after confirming or selecting a package manager.

That keeps the default experience fast and offline-capable after install.

## Using a custom registry

Pass `--registry` to point `tuckshop` at another registry document:

```bash
npx tuckshop --registry https://example.com/registry.json list
```

You can also set an environment variable:

```bash
export TUCKSHOP_REGISTRY="https://example.com/registry.json"
npx tuckshop list
```

Resolution order is:

1. `--registry <url-or-path>`
2. `TUCKSHOP_REGISTRY`
3. `./registry.json` in the current working directory
4. the registry document bundled into the CLI package (after install / `prepack`)
5. workspace fallback `packages/registry/registry.json` during local development
